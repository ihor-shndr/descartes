# Пакетне перенесення «Медитацій» із PDF

Одна задача = одна сторінка читача + чотири мовні версії. Один subagent Terra виконує задачу, координатор перевіряє та об'єднує результати. Скрипти готують матеріал і перевіряють структуру; LLM звіряє текст, заголовки, абзаци та межі рядків із зображенням.

## Запуск у чаті

> Прочитай scripts/import-pages/prompts/batch.md і оброби сторінки 20–25. Використовуй по одному subagent gpt-6.1-terra на сторінку. Після перевірки додай їх у сайт і збери проєкт.

Починайте з 3–5 сторінок. Для відновлення достатньо назвати той самий діапазон: підготовлені матеріали зберігаються, а однакові сторінки при merge не дублюються. Інший PDF або іншу прив'язку готуйте в новій папці через `--work` (цей параметр потрібен і в check/merge).

## Команди з кореня репозиторію

Потрібні Python 3 і macOS зі Swift/PDFKit. Додаткові Python-пакети та API-ключі не потрібні. LLM запускає координатор через доступні subagent tools; скрипт сам моделі не викликає.

```sh
python3 scripts/import-pages/import_pages.py status
python3 scripts/import-pages/import_pages.py prepare --pdf 'temp_docs/Медитації 2021.pdf' --pages 20-25 --anchor-page 20 --anchor-pdf 148
python3 scripts/import-pages/import_pages.py check --pages 20-25
python3 scripts/import-pages/import_pages.py merge --pages 20-25
npm run build
```

Якщо написання назви PDF у файловій системі відрізняється, передайте фактичний шлях. `anchor-pdf` — індекс PDF, починаючи з 1. Скрипт пропонує дві послідовні PDF-сторінки на кожну сторінку читача; агент обов'язково перевіряє друкований латинський номер на кожному зображенні. Для винятків/ранніх сторінок: `--map mapping.json` замість anchor, формат `{"20":[148,149],"21":[150,151]}`. Загальну формулу для всієї книжки не встановлено.

Для кожної сторінки в `temp_docs/import/020/` з'являться:

- `input.json`: номер, прив'язка до PDF і SHA-256 джерела;
- `pdf-148/`, `pdf-149/`: PNG та текст/координати символів;
- `examples.json`: зразки наявних сторінок із заголовками;
- `result.json`: результат, який записує агент за `prompts/page.md`.

Кожен агент працює лише у своїй папці. `merge` спочатку перевіряє весь пакет, потім додає сторінки до `public/meditations/text/{la,la-ua,fr,fr-ua}.json`. Існуючі сторінки з іншим вмістом не перезаписує. Заміни існуючого тексту потрібно розглядати окремо. `docs/` оновлюється звичайною збіркою. Старі `la.md`/`la-converted.json` у цьому процесі не використовуються.

Для заповнення трьох відсутніх перекладів на вже готових латинських сторінках можна обмежити запис:

```sh
python3 scripts/import-pages/import_pages.py merge --pages 3-6 --languages la-ua fr fr-ua
```

Агент усе одно готує чотири мови для звірки; існуючий латинський JSON при такому merge не змінюється. Прив'язку до PDF для ранніх сторінок потрібно встановити окремо.

Пілот на сторінці 20 виконаний через `gpt-6.1-terra`: усі чотири блоки імпортовано, 31 латинський рядок перевірено в браузері, збірка пройшла. Сторінки зі складними заголовками ще потребують окремого пробного проходу. Перевірка інструментів: `python3 -m unittest discover -s scripts/import-pages -p 'test_*.py'`.

Сторінки 7–10 — передмова, яку це видання подає лише латиною й українською. Для них мапа повторює той самий PDF-індекс двічі; відсутні французькі джерела агент позначає `null` у `texts` та пояснює в `review.unavailableLanguages`. Merge пропускає ці версії. Відсутність джерела не є дозволом створювати новий переклад. Номера 11 у латинській пагінації цього видання немає: після 10 йде 12.

## Що потребує уваги

- PNG — основне джерело для верстки. PDF text layer може пропускати символи/пробіли та міняти порядок блоків; координатні рядки — лише підказка. Нечитабельне місце лишається issue і блокує merge.
- Латинські рядки зберігаються фізично, включно з переносами. В інших мовах переноси верстки прибираються, абзаци зберігаються через початковий пробіл. Заголовки отримують `h1/h2/h3`.
- Для латинських заголовків, що входять у друковану нумерацію, задавайте `startLine` і зберігайте кожний фізичний рядок окремо. Рендер і пошук у покажчику враховують такі блоки; наступний абзац теж може мати `startLine`. Приклад — сторінка23: заголовки19–21, продовження тексту з22. Старі заголовки без метаданих зберігають попередню поведінку.
- Продовження з попередньої сторінки може починатися посеред слова або фрагмента. Зберігайте друковані межі сторінок, перевіряйте сусідні сторінки й не вигадуйте маркер `(1)`.
- Різниці маркерів між мовами можуть бути в оригіналі. Потрібне пояснення з прив'язкою до зображення. `check` приймає документований виняток; координатор має його прочитати.
- PASS означає коректну структуру й задекларовану агентом візуальну перевірку, а не математичну гарантію точності. Початок/кінець блоків, підозрілі місця й межі сторінок перевіряє координатор.
- Покажчики не генеруються заново: збережені латинські рядки та маркери дозволяють використовувати наявні посилання. Повнота покажчиків перевіряється окремо.

Робочі PDF, картинки та результати лишаються в `temp_docs/`, яка наразі не відстежується Git. Для довготривалого збереження результатів потрібна резервна копія або окреме рішення, що комітити.

## Прив'язка початкових сторінок

`mapping-initial.json` містить перевірені PDF-індекси для сторінок 3–10 і 12–19 цього видання. Цей пакет уже перенесено: українська з латини є на всіх наявних сторінках до20, французька пара — на1–6 і12–20. Сторінки21–40 також перенесено в усіх чотирьох мовах; наступний пакет починається з41.

Підтверджені друкарські повтори маркерів зберігаються з `review.duplicateMarkers` (language, marker, reason). Координатор перевіряє обидва входження на зображенні; непояснені повтори блокуються.

Перевірка друкованої нумерації та інтерактивних маркерів у заголовках: `node_modules/.bin/tsx --tsconfig scripts/import-pages/tsconfig.verify.json scripts/import-pages/verify-line-numbering.ts`. Цей локальний tsconfig також дозволяє перевірити саме src/: `node_modules/.bin/tsc --noEmit -p scripts/import-pages/tsconfig.verify.json`.
